# 05｜安全、越狱与 Prompt Injection 的机制框架

> 本章只讨论防御性机制理解与无害研究设计，不收录可直接复用的攻击载荷、危险步骤或针对真实系统的操作指南。

## 5.1 安全不是一个外部“绝对 if 语句”

在模型外部，系统可以有硬权限、工具白名单、内容过滤器和沙箱；但模型内部的安全行为仍由训练得到的表示与回路实现。一个简化链条是：

```text
识别输入内容与来源
   → 表征任务、角色、权限、危险性
   → 形成拒绝 / 澄清 / 安全替代等行为状态
   → 与任务完成、语法、persona、事实回答路径竞争
   → 生成首 token
   → 自回归延续或纠正
```

任何一处失配都可能产生不安全输出或过度拒绝。

## 5.2 四个不能混淆的变量

### 内容表征

模型是否形成了完整任务语义，而不是只处理局部字符、词或格式？

### 有害性/风险表征

模型内部是否把请求归入危险、越权、欺骗或其他风险类别？

### 拒绝/安全行为表征

模型是否进入准备拒绝、澄清、限制范围或重定向的状态？

### 最终行为

安全路径是否在 token 竞争中获胜并持续到完整响应？

这四者可以分离。模型可能“知道有风险”但仍输出；也可能因表面特征触发拒绝，却没有正确理解实际无害任务。

## 5.3 越狱的通用机制分解

越狱不是单一现象，下列机制可以独立或组合出现。

### A. 组合识别延迟

拆分、间接表达、编码、跨位置拼接或多步任务，可能让局部表示先驱动输出，而整体危险语义尚未形成。On the Biology 中的案例表明，模型可以由多条局部路径分别为字母或输出片段投票，但在决策关键点之前没有形成统一危险概念。

后果：安全判断晚于任务执行路径。

### B. 表面任务压过真实意图

模型可能优先表征“翻译、续写、分类、角色扮演、代码补全、引用文本”等表面任务，而没有把嵌入内容视为应受同等安全约束的待执行目标。

后果：任务类型特征改变了安全规则的调用方式。

### C. 角色和权限混淆

系统指令、用户输入、检索文档和工具返回最终都被编码成可学习表示。虽然消息边界和角色 token 提供重要信号，但它们不是密码学访问控制。模型可能受到措辞、风格、伪造标签或对话惯例影响，错误判断“谁在发指令”。

后果：不可信数据被当作控制信号。

### D. 安全路由受干扰

风险特征可能已经激活，但后续 attention 没有把它读到拒绝路径，或任务路径通过 QK 交互改变了注意力目标。安全不仅是最终 logit 上加一个负数；它可以改变模型读取什么、忽略什么。

### E. 行为路径竞争

最终 logits 可以概念性地写成：

$$
z_v=z_v^{task}+z_v^{syntax}+z_v^{persona}+z_v^{safety}+z_v^{memory}+\cdots.
$$

越狱可能不是“安全信号归零”，而是其他倾向在关键 token 上更强。

### F. 首 token 与语法锁定

一旦输出进入回答式句子、列表、代码或特定角色，语法和承诺会要求完成当前结构。模型可能在后续 token 才形成风险表征，但中途切换到拒绝会破坏局部连贯性。

### G. 分布外组合

安全训练覆盖有限。罕见语言、格式、工具链、长上下文和多轮组合可能进入训练中约束不足的区域，暴露快捷规则和未预期路径。

## 5.4 成功与失败越狱为何都重要

April 2025 update 对一个失败越狱的分析给出重要方法论：

- 相似表面输出可能由不同内部原因产生；
- 特征可视化若只基于狭窄数据会误导；
- 模型可能对无害的拆分形式过度拒绝；
- 归因图可以引导发现现象，但 error nodes 仍可能使根因未知；
- 已生成的拒绝开头会反过来让模型补全一个并非用户请求的危险动作。

因此不能只比较“是否拒绝”，还要研究拒绝理由、触发时点、路径和反事实。

## 5.5 过度拒绝与越狱是镜像问题

### 越狱

真实风险存在，但整体识别、安全路由或输出竞争失败。

### 过度拒绝

真实风险不存在，但表面危险词、拆分形式、角色或已生成拒绝前缀错误激活安全路径。

两者都说明安全分类不是独立、完美的符号规则，而是嵌入条件计算系统中的近似机制。

## 5.6 Prompt injection 与内容越狱的区别

### 内容越狱

目标通常是让模型绕过内容/行为政策。

### Prompt injection

目标通常是让模型把不可信文本当成指令，覆盖预期任务或调用权限。它是**控制平面与数据平面混用**的问题。

对带工具的 agent，安全边界不能只依赖模型“理解优先级”。系统还需要：

- 来源与权限在模型外部强制标记；
- 最小权限工具与参数校验；
- 不可信内容隔离；
- 敏感操作的确定性策略或人工确认；
- secret 不直接进入可被任意文本影响的上下文；
- 工具调用结果与文本输出分层审计；
- 沙箱、速率限制和可撤销动作。

prompt engineering 可以降低风险，但不能替代访问控制。

## 5.7 “单一拒绝方向”怎样正确理解

一些模型中可以找到低维方向，增强或削弱它会显著改变拒绝行为。这是重要因果证据，但不能推出：

- 所有安全行为都由一个方向实现；
- 所有模型共享同一方向；
- 有害性识别和拒绝是同一变量；
- 移除方向就解释了完整越狱机制；
- 模型外部安全层不重要。

更稳妥的模型是：拒绝行为可能在某些位置具有低维读出或瓶颈，同时上游有多种风险特征、注意力路径和冗余回路。

## 5.8 防御性实验设计

### 无害权限代理

在沙箱中使用虚构系统规则、普通字符串和假工具，测试不可信文档是否能改变任务。不要使用真实秘密、真实账户或破坏性工具。

### 语义组合实验

使用无害概念，比较完整词、拆分字符、首字母、同义改写和跨位置引用，测量整体概念形成时间与输出模式。

### 判断—行为解耦

先让模型对无害代理任务进行风险分类，再观察是否按分类行动；白盒模型可分别训练内容 probe 与行为 probe，并做独立 steering。

### 前缀干预

固定同一 prompt，提供回答式、澄清式或拒绝式的无害首句，观察后续轨迹差异。这检验自回归反馈，不等于研究真实危险载荷。

### 路由验证

在开放模型中使用 activation patching 或 head/feature ablation，检查安全相关信号是否存在、是否被下游读取、在哪个 token 前后失去控制。

## 5.9 最低报告要求

安全机制报告至少说明：

- 模型与精确版本；
- system/user/tool 消息边界；
- tokenizer 与上下文长度；
- 外部过滤器是否参与；
- 目标行为和无害代理；
- 成功、失败、过度拒绝和边界案例；
- 黑盒行为、probe、干预和 patching 分别支持什么；
- 不公开可直接复用的有效攻击字符串。
