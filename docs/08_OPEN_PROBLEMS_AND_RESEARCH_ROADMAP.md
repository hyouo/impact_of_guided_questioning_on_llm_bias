# 08｜开放问题与研究路线

## 8.1 总目标

长期目标不是给每个神经元贴标签，而是建立能预测模型行为的多尺度理论：

```text
训练数据与优化
  → 表征基底与几何
  → 条件回路与全局权重
  → 推理、规划和安全行为
  → agent 环境中的权限与后果
```

真正成功的理论应能在未见 prompt、未见模型或训练变化上做可检验预测。

## 8.2 表征问题

### 特征是否可识别

- 在什么假设下，特征词典可以唯一或近似唯一？
- feature splitting 是真实细化还是字典容量产物？
- 离散特征、子空间和流形怎样统一？
- 非线性、关系型和绑定特征怎样表示？
- 怎样量化 error term 中仍有多少重要计算？

### 跨层生命周期

- 特征是在一层产生、跨层持续，还是不断旋转重编码？
- crosscoder 的共享特征与真实因果单元是什么关系？
- 能否自动区分“保持同一变量”和“仅线性相关的不同变量”？

## 8.3 计算与回路问题

### 从局部执行轨迹到全局程序

- 如何把 prompt-specific attribution graph 合并成可复用回路模板？
- 如何表示输入条件、分支、循环和序列反馈？
- 如何发现层次化宏变量，降低数百万特征的复杂度税？
- 如何处理多条冗余路径和干预后的补偿？

### 干扰权重

- effectiveness/helpfulness 能否扩展到多层大模型？
- 如何无需枚举全部特征对就识别无效连接？
- 最优基底是否能显著减少有帮助权重数量？
- 干扰权重与 adversarial examples、越狱和脆弱性有何因果关系？

### Attention

- 如何在全数据分布上给高秩 head 建立简洁功能描述？
- QK 与 OV 的多任务复用是否有共同低维结构？
- 多头如何协同构造流形、执行路由和校验？
- RoPE、GQA/MQA、稀疏 attention 等架构如何改变经典 QK/OV 理论？

## 8.4 推理问题

- 模型何时使用记忆、启发式或可泛化算法？
- 如何自动检测预计算答案、计划和中间变量？
- 层维度与序列维度计算怎样分工？
- CoT 在什么条件下忠实，何时是控制工具而不是解释？
- J-space 是否跨模型、规模和训练方法稳定？
- 可报告性与可控制性是否来自同一几何结构？

## 8.5 训练与模型差异

- 预训练先形成哪些语义结构，后训练新增哪些行为路由？
- RLHF/RLAIF 是创建新能力、重用旧特征还是改变读出？
- 模型版本更新中，安全行为变化对应参数、特征还是回路层变化？
- 能否从训练样本预测某个特征或回路的形成？
- memorization、generalization、grokking 和 superposition 如何统一？

## 8.6 安全问题

- 危险性识别、权限判断、拒绝和安全替代的共同架构是什么？
- 为什么某些输入导致安全信号存在但未控制输出？
- 如何区分越狱中的识别延迟、路由干扰和首 token 锁定？
- 如何在不发布攻击载荷的情况下复现实验？
- 外部访问控制与内部模型表征如何形成可证明的组合安全？
- 模型的 persona、功能情绪、评估意识和计划状态怎样影响安全决策？

## 8.7 工具与自动化

- 自动解释系统怎样避免生成貌似合理的机制故事？
- NLA/activation oracle 的自然语言瓶颈能否获得可校准的置信度？
- 解释代理怎样调用 feature browser、HeadVis、patching 与数据搜索，并保留证据链？
- 如何建立机制可解释性 benchmark，不奖励表面标签而奖励反事实预测？
- 如何让可视化支持数百万特征、长上下文和多模型对比？

## 8.8 本仓库的可执行路线

### Phase 1：理论规范化

- 维护完整来源目录；
- 为每个结论标注对象、范围和证据等级；
- 统一术语：参数/激活/特征/回路/行为；
- 收集反例和方法失败案例。

### Phase 2：最小玩具模型

- 固定权重与输入条件激活；
- superposition 与干扰连接；
- attention QK/OV 的小型可视化；
- 首 token 反馈与轨迹分叉；
- probe 与 causal intervention 的差异。

### Phase 3：开放模型白盒实验

- 选择小型、可复现 transformer；
- 记录 tokenizer、版本和权重 hash；
- 提取 residual stream、MLP 与 attention 激活；
- 建立 SAE/probe/patching 基线；
- 使用无害任务研究角色、格式和安全代理。

### Phase 4：局部回路复现

- induction、copy、multiple-choice selection、计数或 line-breaking；
- 对每个机制做必要性、充分性和 interchange 测试；
- 对失败案例分析 error term 和替代路径；
- 比较 feature view 与 geometry view。

### Phase 5：跨模型与训练阶段

- 使用 crosscoder 或对齐方法比较 base/instruct/checkpoint；
- 测试后训练对 persona、拒绝和报告空间的影响；
- 研究同一行为在不同模型中是否机制同构。

## 8.9 项目选择原则

优先选择：

- 模型稳定、输出可自动验证的自然任务；
- 可构造干净反事实和强对照；
- 失败结果同样能约束理论；
- 不需要真实危险载荷；
- 能连接局部回路与更一般理论。

不优先选择：

- 只看一次聊天截图；
- 用同一 LLM 生成、评分并解释结论；
- 仅凭 attention heatmap 命名头；
- 只展示 steering 成功、不报告副作用；
- 在 API 黑盒上声称特定内部神经元机制。

## 8.10 里程碑定义

一个阶段性理论进展应至少满足一种：

1. 预测一个未见 prompt 的内部状态和行为；
2. 找到能区分两个机制假设的反事实干预；
3. 把复杂特征图压缩为更简洁且不降低预测力的几何/算法描述；
4. 在另一个模型中复现相同机制，或明确证明机制不同；
5. 从训练变化预测回路变化；
6. 构造能提升安全性的外部控制，并解释其作用边界。
