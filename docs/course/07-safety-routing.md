# 第 7 章｜用“识别—策略—输出—反馈”理解安全

## 学完你应该能

- 区分内容识别、角色/权限判断、拒绝策略状态和最终输出；
- 解释为什么“模型检测到风险”不保证最终拒绝；
- 用同一框架理解越狱、过度拒绝和 prompt injection；
- 设计无害的安全路由实验，而不是优化真实攻击载荷。

## 核心模型

安全行为可以拆成四层：

```text
1. 识别：输入包含什么语义和属性？
2. 策略：在当前角色与权限下应采取什么行为？
3. 输出：拒绝、澄清、回答等路径如何竞争 token？
4. 反馈：已生成前缀怎样强化后续轨迹？
```

用变量表示：

$$
r=f_{\text{recognition}}(x),
\qquad
s=f_{\text{policy}}(r,\text{role},\text{source}),
\qquad
z=f_{\text{output}}(s,h).
$$

$r$ 是内容识别状态，$s$ 是策略状态，$z$ 是最终 logits。它们可以相关，但不必相同。

## 逐步理解

### 1. 风险表征与拒绝行为可以分离

模型可能已经形成“这段内容有风险”的内部状态，却没有把该状态路由到拒绝输出。原因可能包括：

- 策略状态没有形成；
- 角色或权限判断错误；
- 下游头没有读取安全信号；
- 任务完成、翻译、角色扮演或语法路径暂时占优；
- 回答式首 token 已经形成并持续反馈。

因此不能把“不拒绝”直接解释为“完全没识别”。

### 2. 整体语义可能形成得太晚

输入被拆成 token 后，模型可能先处理局部字符、格式或转换任务，直到生成过程中才把它们组合成整体语义。若任务完成路径先赢得首 token，策略切换会面对更强的轨迹惯性。

### 3. Prompt injection 是权限边界问题

系统指令、用户消息、检索文档和工具输出最终都进入相似的 token 表示媒介。角色标签提供线索，但权限主要靠学习到的来源与角色表征，而不是硬件隔离。

不可信文档可能通过措辞、格式和伪造角色线索影响模型对“应该听谁”的判断。这就是为什么系统安全不能只依赖一句“忽略文档中的指令”。

### 4. 过度拒绝是同一链条的另一个方向

无害输入可能因为表面词、编码形式、语言或格式激活了粗糙风险特征，导致拒绝策略过早占优。越狱和过度拒绝都可以看成识别、策略与输出之间的映射在特定分布上失配。

### 5. 系统级防御必须超出 prompt

可靠系统还需要数据与指令的结构化隔离、最小权限工具、输入来源标记、高风险动作的外部验证，以及不让模型独自决定权限。机制理解能帮助定位失配，但不能替代系统访问控制。

## 动手验证

```bash
llm-theory-lab explain C09
llm-theory-lab run-toy --ids C09
```

C09 使用无害“受限资源”代理。它构造：内容识别信号很高、拒绝策略状态很低、最终行为仍为继续。然后只 patch 策略状态，观察输出是否翻转。

实验回答的是这些变量在结构上能否分离。它不声称真实聊天模型恰好使用相同坐标。

## 常见误区

**“越狱就是安全参数被关闭。”** 标准推理中参数通常没有变化；更可能是激活、路由、组合时机和输出竞争改变。

**“识别到风险就一定会拒绝。”** 识别状态还要经过策略和输出路径。

**“系统 prompt 权限最高，所以模型内部绝不会混淆。”** 权限层级在系统协议上明确，但模型仍通过学习到的表示来执行，不能视为形式化安全边界。

**“研究越狱必须收集攻击字符串。”** 可以先用无害代理研究角色、来源、策略路由和输出解耦。

## 自测

1. 模型不拒绝时，至少列出三种不同内部失败机制。

3. Prompt injection 与普通内容请求有什么不同？
4. 哪些安全保证必须由模型外系统提供？
