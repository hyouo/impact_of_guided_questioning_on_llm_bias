# 实验协议：怎样把“大模型理论”变成可反驳实验

## 1. 从理论句子到实验

每个实验使用下面的理论卡：

```text
Claim：希望检验的具体命题
Object：参数、激活、特征、头、路径、logit、token 或行为中的哪一个
Scope：哪类模型、任务、输入和运行条件
Intervention：改变什么，其余什么保持不变
Controls：正对照、负对照、随机对照、格式对照
Metric：在看到结果之前定义的量
Falsifier：什么结果会削弱或推翻当前解释
Evidence level：该实验最多能支持到哪一层结论
Forbidden inference：不能从该结果推出什么
```

“不改变权重但回答变了”不是完整命题。更可测试的版本是：

> 在同一固定参数模型中，只改变输入状态的任务证据维度，会改变某组隐藏特征及输出 top token；重复执行完全确定。

## 2. 变量分层

必须先说明研究对象属于哪一层：

| 层 | 变量 | 常见干预 |
|---|---|---|
| 训练 | 样本频率、损失权重、优化器 | 重训、数据重加权、stage-wise diffing |
| 参数 | 原始矩阵、虚拟权重 | 参数消融、低秩修改、权重分解 |
| 激活 | residual、MLP、Q/K/V、特征 | patch、ablation、steering、pinning |
| 路由 | attention score、softmax、专家 gate | key/query 扰动、头消融、路由 patch |
| 输出 | logits、概率、采样 token | logit lens、温度、top-p、强制 prefix |
| 轨迹 | 已生成前缀、KV cache、后续状态 | prefix counterfactual、多步生成 |
| 系统 | role、工具、权限、外部数据 | 信任边界测试、结构化消息隔离 |

不同层的结论不可偷换。例如，输出差异不能自动解释为参数改变；probe 成功不能自动解释为路由使用。

## 3. 对照设计

### 3.1 正对照

选择一个理论上应该改变输出的干预，确认指标能检测到效应。C07 中消融真正被输出头读取的维度就是正对照。

### 3.2 负对照

改变同规模但理论上无关的变量。C08 中 patch 无关维度就是负对照。没有负对照的 patching 很难排除“任何大扰动都会改变输出”。

### 3.3 匹配对照

比较 prompt 时，尽量匹配：

- token 数量；
- 目标 token 位置；
- 标点和模板；
- 词频与长度；
- 聊天角色；
- 上下文窗口占用。

若无法匹配，应在报告中承认干预同时改变了哪些因素。

### 3.4 方向对照

Steering 或 patching 应测试：

- 正方向；
- 负方向；
- 随机等范数方向；
- 相邻层和位置；
- 不同强度。

只有目标方向呈现预测的剂量反应，解释才更可信。

## 4. 指标

### 4.1 Logit difference

对目标 token $i$ 和对照 token $j$：

$$
\Delta z = z_i-z_j.
$$

它比只看生成文本更敏感，也不受一次采样随机性支配。

### 4.2 Probability odds

正温度 $T$ 下：

$$
\log\frac{p_i}{p_j}=\frac{z_i-z_j}{T}.
$$

不要在数学公式中把 $T=0$ 代入；greedy 是极限或 API 约定，不是正常 softmax 温度。

### 4.3 Patch restoration

$$
R=
\frac{m_{patched}-m_{corrupted}}
     {m_{clean}-m_{corrupted}}.
$$

$R\approx1$ 表示 patch 对指标恢复接近 clean；$R>1$ 可能是过度恢复；$R<0$ 表示反向影响。必须同时报告分母和原始指标。

### 4.4 分布差异

Jensen–Shannon divergence 对称且有限，适合比较完整 next-token 分布。但它只说明分布不同，不解释差异由哪条内部路径产生。

### 4.5 行为指标

长文本评分必须预先定义 rubric，并尽量使用：

- 人工盲评；
- 多个独立评估器；
- 可程序化规则；
- 评估器一致性；
- 原始文本与失败案例。

不应再次回到“让同一模型给自己生成的输出打一个总分”的旧方法。

## 5. 统计与复现

开放模型实验至少跨：

- 多个模板；
- 多个语义实例；
- 多个随机种子；
- 多种干预强度；
- 一个以上模型或 checkpoint；
- clean/corrupted 对调；
- 预先指定的排除规则。

报告均值、离散程度、样本数和效应分布，不只挑最好案例。PyTorch 的相同 seed 也不保证跨平台和版本逐位一致，因此环境版本是结果的一部分。

## 6. 解释升级路径

```text
观察到相关性
  → 构造最小对照
  → 做内部干预
  → 加正负对照
  → 跨实例复现
  → 预测未测试的反事实
  → 独立实现复现
```

只有最后几步才能把“可读故事”逐渐升级为机制理论。

## 7. 安全研究

安全实验使用无害代理类别和访问控制任务。允许研究的机制问题包括：

- 分类信号是否存在；
- role/authority 是否被正确表示；
- policy state 是否形成；
- policy state 是否被输出层读取；
- 回答式前缀是否压过策略状态；
- 消融或 patch 是否恢复预期安全动作。

不把搜索目标设为“提高真实攻击成功率”，不收集或发布可直接复用的绕过字符串。
